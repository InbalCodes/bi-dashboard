# מערכת BI ואנליטיקה מבוססת AI — STSICONIC

מערכת אינטרנטית שמתחברת ל-Google Sheets, מייבאת נתוני שיווק ומכירות, מציגה אותם בדשבורד ניהולי עם סינון וגרפים, ומשתמשת ב-AI (Claude) כדי לנתח ביצועים, לענות על שאלות חופשיות וליצור דוחות ותמונות (Gemini/Imagen).

## מבנה המערכת

- **Next.js 16 (App Router, TypeScript)** — פרויקט full-stack אחד: עמודי React בצד לקוח + Route Handlers (`src/app/api/**`) בצד שרת, ללא שרת נפרד.
- **Postgres (Neon)** — עותק מסונכרן של הגיליון (טבלת `marketing_rows`, ראו `db/schema.sql`). נדרש כי Vercel הוא serverless וללא מסד נתונים לא ניתן לשמור סטטוס סנכרון בין בקשות, למנוע כפילויות בסנכרון חוזר, או לתמוך בעדכון שורות קיימות.
- **Recharts** — 7 גרפים בדשבורד.
- **jose** — session cookie חתום (HMAC) למסך ההתחברות.

מבנה תיקיות עיקרי:

```
src/
  app/
    (app)/            # מסכים מוגנים: dashboard, insights, ask, report, settings (+ layout עם ניווט)
    login/             # מסך התחברות
    api/
      sync, sync/status, cron/sync   # שלב 1 - Google Sheets
      metrics, charts, filters/options  # שלב 2-3 - דשבורד וסינון
      ai/analyze, ai/ask, ai/report, ai/image  # שלב 4-7 - AI
      auth/login, auth/logout
  lib/
    db.ts, sheets.ts, parse.ts, sync.ts   # שכבת נתונים וסנכרון
    filters.ts, metrics.ts, compare.ts    # אגרגציות ומסננים
    auth.ts                                # session
    ai/digest.ts, ai/claude.ts, ai/gemini.ts, ai/schemas.ts
  components/          # רכיבי UI (FilterBar, KpiCards, DashboardCharts, AnalyzePanel, AskPanel, ReportPanel...)
  proxy.ts             # הגנת נתיבים (המקביל ל-middleware בגרסאות קודמות של Next.js)
db/schema.sql          # סכימת המסד
scripts/init-db.ts      # יצירת הטבלאות
```

## חיבורי API

| שירות | לשם מה | קובץ מרכזי |
|---|---|---|
| Google Sheets API | קריאת הנתונים מהגיליון (Service Account, קריאה בלבד) | `src/lib/sheets.ts` |
| Postgres (Neon) | עותק מסונכרן של הנתונים + לוג סנכרון | `src/lib/db.ts` |
| Anthropic Claude | תובנות, שאלות חופשיות, דוחות, בניית prompt לתמונה | `src/lib/ai/claude.ts` |
| Google Gemini/Imagen | יצירת תמונות (שלב 7) | `src/lib/ai/gemini.ts` |

הסנכרון (`POST /api/sync`) קורא את כל הגיליון, מנרמל כל שורה (`src/lib/parse.ts`), ומבצע `UPSERT` לפי `row_id` (=`מזהה שורה`) — כך שסנכרון חוזר לא יוצר כפילויות, ושורה שהשתנתה בגיליון מתעדכנת. כל ניסיון סנכרון נרשם בטבלת `sync_log` (גם הצלחה וגם כישלון, עם הודעת שגיאה).

## איך הנתונים מועברים למודל ה-AI

שום קריאה ל-AI לא מקבלת שורות גולמיות מה-DB וגם לא טקסט חופשי. במקום זאת, `src/lib/ai/digest.ts` מחשב "digest" — אובייקט JSON קומפקטי המבוסס על אותם חישובי אגרגציה שמזינים את הדשבורד עצמו (`getMetrics`, `getCharts`), **מסונן לפי אותם מסננים שנבחרו במסך**. ה-digest הזה הוא הקלט היחיד שנשלח למודל בכל אחת מארבע היכולות (ניתוח, שאלות, דוח, בניית prompt לתמונה). זה מבטיח שהתשובה תמיד תואמת בדיוק את מה שהמשתמש רואה על המסך.

התשובות עצמן מוחזרות דרך [tool use](https://docs.claude.com/en/docs/build-with-claude/tool-use) עם JSON Schema קשיח (`src/lib/ai/schemas.ts`) ולא כפרוזה חופשית — כך שאין תלות בפרסור טקסט שביר, והפלט מובנה ובדוק מראש.

## איך נמנעות תשובות שאינן מבוססות נתונים

1. **קלט מוגבל**: המודל מקבל אך ורק את ה-digest המספרי המחושב בשרת — אין לו גישה לשום מקור מידע אחר.
2. **System prompt מחייב** (`ANTI_HALLUCINATION_SYSTEM_PROMPT` ב-`src/lib/ai/claude.ts`): אוסר במפורש לחשב/לנחש מספרים שלא מופיעים ב-JSON, ואוסר להזכיר קמפיין/איש מכירות/ערוץ/אזור/מוצר שלא מופיע ברשימת `knownEntities` שבתוך ה-digest עצמו.
3. **ולידציה בצד שרת**: כל שם ישות שהמודל מחזיר בשדות `standoutCampaigns` / `standoutSalespeople` (ב-`/api/ai/analyze`) נבדק בפועל מול `knownEntities` (הנגזר מהנתונים המסוננים בפועל, לא מכל הטבלה) — פריט עם שם לא-קיים נמחק לפני ההצגה, ומוצגת אזהרה שקופה למשתמש (`warnings`).
4. **שקיפות מלאה**: בכל מסך AI (תובנות AI/שאלות על הנתונים/דוח ניהולי חכם) יש כפתור "הצגת הנתונים שעליהם מבוסס הניתוח" שמציג את ה-digest המדויק שנשלח למודל — לא תיאור, אלא הנתונים בפועל.
5. **הודעת "אין מספיק נתונים"**: בשאלות חופשיות, השדה `hasEnoughData` מאפשר למודל להצהיר במפורש שאין לו מספיק מידע לענות בביטחון, במקום להמציא תשובה.

## עיבוד ונרמול הנתונים

בהתאם לכללי המשימה, בוצעו רק התאמות טכניות, ללא שינוי נתונים:

- **תאריך**: מומר מ-`DD/MM/YYYY` (כפי שמוגדר בגיליון) לפורמט ISO לצורך שמירה בעמודת `DATE`.
- **תקציב ואזור**: ערכים חסרים (בכוונה, לפי מילון השדות) נשמרים כ-`NULL` ולא כ-0 או מחרוזת ריקה — כדי לא לעוות ממוצעים או להציג "אזור לא ידוע" כאזור אמיתי.
- **חלוקה באפס**: כשמספר העסקאות או הלידים הוא 0, מדדים כמו עלות ממוצעת לעסקה/לליד ו-ROI מוצגים כ-`—` ולא כ-`NaN`/`Infinity` (ראו `divideOrNull` ב-`src/lib/metrics.ts`).
- **מזהה ייחודי**: `row_id` (=`מזהה שורה` בגיליון) הוא מפתח ה-`UPSERT`, כנדרש למניעת כפילויות.
- **שורות לא תקינות**: שורה עם תאריך לא תקין או שדה טקסט/מספר חובה חסר (לא כולל תקציב/אזור) מדולגת ומדווחת למשתמש במסך ההגדרות, ולא נכנסת למסד הנתונים.
- **החלטות מדידה**: "קמפיין מוביל" ו-"ערוץ הפרסום המוביל" מחושבים לפי **הכנסות** (לא כמות לידים) — זהו המדד שהכי משקף רווחיות בפועל.

## הפעלה מקומית

דרישות: Node.js 20.9 ומעלה, חשבון Neon (או כל Postgres נגיש), Service Account של Google עם גישת קריאה לגיליון, מפתחות Anthropic ו-Gemini.

```bash
npm install
cp .env.local.example .env.local
# ערכו את .env.local עם הערכים האמיתיים (ראו טבלת משתני הסביבה למטה)
npm run db:init   # יוצר את הטבלאות בפוסטגרס
npm run dev       # http://localhost:3000
```

## משתני סביבה

כולם מוגדרים ב-`.env.local` (לא מחובר ל-git) — ראו `.env.local.example` למבנה המלא.

| משתנה | תיאור | מאיפה משיגים |
|---|---|---|
| `DATABASE_URL` | חיבור לפוסטגרס | Neon dashboard / Vercel Postgres integration |
| `GOOGLE_SHEETS_SPREADSHEET_ID` | מזהה הגיליון (מתוך ה-URL שלו) | Google Sheets |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | אימייל ה-Service Account | Google Cloud Console → IAM |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | המפתח הפרטי (JSON key) | Google Cloud Console — יש לשתף את הגיליון עם האימייל הזה כ-Viewer |
| `GOOGLE_SHEETS_RANGE` | שם/טווח הגיליון (ברירת מחדל: `נתונים`) | אופציונלי |
| `ANTHROPIC_API_KEY` | מפתח Claude | console.anthropic.com |
| `ANTHROPIC_MODEL` | דגם Claude (ברירת מחדל: `claude-sonnet-5`) | אופציונלי |
| `GEMINI_API_KEY` | מפתח Google AI (Gemini/Imagen) | aistudio.google.com |
| `GEMINI_IMAGE_MODEL` | דגם יצירת התמונות (ברירת מחדל: `gemini-2.5-flash-image`) | אופציונלי |
| `AUTH_SECRET` | סוד לחתימת ה-session cookie (מחרוזת אקראית ארוכה) | ליצור בעצמכם |
| `DEMO_USER_EMAIL` / `DEMO_USER_PASSWORD` | פרטי המשתמש לצורך התחברות | ליצור בעצמכם |
| `CRON_SECRET` | מגן על `/api/cron/sync` מפני קריאות לא מורשות | ליצור בעצמכם |

## פריסה לשרת (Vercel)

1. `git push` הריפו ל-GitHub, ואז ייבוא הפרויקט ב-[vercel.com/new](https://vercel.com/new).
2. הוספת Postgres (Neon) דרך Vercel Marketplace/Storage — זה ימלא את `DATABASE_URL` אוטומטית.
3. הגדרת שאר משתני הסביבה בהגדרות הפרויקט ב-Vercel (Settings → Environment Variables).
4. לאחר הפריסה הראשונה, הרצת `npm run db:init` **מקומית** מול ה-`DATABASE_URL` של הפרודקשן (או הרצת תוכן `db/schema.sql` ידנית ב-Neon SQL editor).
5. `vercel.json` מגדיר Cron יומי ל-`/api/cron/sync` (רענון נתונים אוטומטי — בונוס). בתוכנית Hobby של Vercel מותר Cron פעם ביום לכל היותר; אפשר לשנות תדירות בתוכניות בתשלום.
6. עדכון קוד בעתיד: כל `git push` ל-branch הראשי מפעיל פריסה אוטומטית ב-Vercel.

## מסכי המערכת

- **מרכז הבקרה השיווקי (דשבורד)** — מדדים מרכזיים, 7 גרפים (הכנסות מול הוצאות, לידים לפי ערוץ, המרה לפי קמפיין, הכנסות לפי איש מכירות, ביצועים לפי מוצר, תקציב מול הוצאה בפועל, משפך מכירות), סינון מלא, השוואה לתקופה קודמת (כשנבחר טווח תאריכים).
- **תובנות AI** — ניתוח מובנה על הנתונים המסוננים: סיכום, 3 תובנות, מגמות, חריגות, קמפיינים/אנשי מכירות חריגים, המלצות, נקודות לבדיקה.
- **שאלות על הנתונים** — שאלה חופשית + תשובה מבוססת-נתונים, כולל הצגת הנתונים שעליהם היא מתבססת.
- **דוח ניהולי חכם** — דוח ניהולי מלא (מדדים, גרפים, תובנות, המלצות) עם ייצוא ל-CSV ול-PDF (הדפסה), ויצירת תמונות AI מבוססות-נתונים.
- **הגדרות נתונים** — מקור הנתונים (קישור לגיליון), מצב חיבור, מועד סנכרון אחרון, סנכרון ידני.
